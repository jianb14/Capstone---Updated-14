# Admin settings and profile

Site Settings uses the same neutral colors, focus rings and controls as Customer Concerns. Section links move within the page; the mobile section list scrolls horizontally. The save bar remains reachable while the sections scroll.

The single save submits business details, logistics rates and design limits together using an AJAX POST. All three Django forms must validate before the transaction writes anything. Field errors appear below their inputs, entered values remain available, and the page does not reload. Native form submission still works without JavaScript. Reset changes restores the last saved form values and shop marker. Editing an address clears the previous coordinates, including when the map service is unavailable.

After a successful settings save, a theme-aware toast stays visible regardless of scroll position and the sticky save bar confirms the save. If newer edits were made while the request ran, feedback says those edits are still unsaved. Failed requests show an error rather than a success notification. My Profile uses the same toast only after email verification or password change has completed. Toasts appear for three seconds with a short entrance and exit animation. Hover, keyboard focus and a hidden browser tab pause the remaining time; leaving resumes that time instead of restarting it. A new result replaces the old toast and starts its own timer. Toasts can be dismissed, respect reduced-motion preferences, and do not rely on external scripts.

Logistics rates apply to new quotes. Existing bookings retain their stored quote. Alert recipients use an email field enhanced with removable tags: Enter or comma adds an address, pasted lists are supported, and duplicates are ignored case-insensitively. Unsaved addresses are included when saving; Reset restores the saved recipients. Invalid addresses show an error below the field and prevent saving. The server also validates and deduplicates the complete list. Without JavaScript the field accepts comma-separated emails. Optional contacts and social links can be left blank.

The public page title, footer business name, contacts and social links read the saved configuration. Blank optional details are hidden. Public templates receive only the six public business fields; alert recipients and booking rules are not exposed through that helper. The values are reused within one rendered request and refreshed on the next request. Social URLs require HTTP or HTTPS, and unsafe legacy URLs are not rendered as links.

Integration coverage in `app.test_site_settings_integration` exercises each saved field, public website output, booking lead time, minimum/maximum duration, overtime, payment/design deadlines, change cutoff, logistics distance rates/caps, design allowance and alert email recipients/toggles. Browser checks in `app.test_site_settings_functional_browser` save every section, reload the saved values, confirm the public footer, and simulate failed connections, expired sessions, server errors, and edits made during a slow save. Drafts remain available for retry, and a repeated submit while saving is ignored.

Admin My Profile presents account information, email verification, password security and the signed-in administrator's five latest audit actions. It remains a read-only account information page. Account role, permissions and other users cannot be edited here.

Email setup continues to use the existing authenticated verification modal. Password change now stays in its own modal for the entire process: current password, new password, email code, verification and completion. The password is not updated until the server accepts the code. Six numeric inputs support paste, keyboard navigation, an expiry countdown, resend cooldown and restarting the form. Closing the modal clears password inputs; a pending code can be resumed after reopening or refreshing. Expired codes show one recovery state and cannot be submitted. Server-side OTP limits and session binding remain authoritative.

Browser coverage is opt-in with `RUN_CONFIGURATION_BROWSER=1` and `app.test_admin_configuration_browser` (Chrome), plus the existing admin email setup browser tests. Use a disposable database and local memory email backend.
