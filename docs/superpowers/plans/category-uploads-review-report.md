# Category uploads and Theme Decor working-tree review

Resolution note from the implementer: the findings below describe the initial review. All nine important findings and the upload identity parity issue were subsequently corrected; focused regressions and browser checks passed. See `2026-11-20-category-uploads-verification.md` for the final evidence and broader baseline comparison.

The reviewed change needs corrections before release. I found nine important issues and no critical issue. Locations refer to the implementation in the supplied review package, before follow-up fixes.

## Important findings

1. **Migration can hide existing catalog assets.** `app/migrations/0122_category_uploads.py:12` accepts an existing built-in without checking its identity or flags. Line 15 adopts the exact category without checking its default assets or other case-equivalent names. `app/design_validation.py:47` subsequently removes its assets from offer evaluation. Detect conflicts and stop with the category and asset identifiers for deliberate resolution before changing the category.
2. **Conversion can overwrite existing offer allowances.** `app/migrations/0123_map_theme_decor_inclusions.py:13` includes unresolved item rows alongside services. Line 18 overwrites a pre-existing requirement for the canonical category, setting its minimum to zero. Restrict conversion to the five approved offers' exact service rows. Preserve established rules and flag contradictory rows for resolution.
3. **Reopening a grouped design changes counts and upload identities.** `static/js/design_rules.js:19` traverses serialized group children. Live Fabric groups expose their children through `getObjects()` or `_objects`. `static/js/design_canvas.js:1153` also rewrites image URLs only at the top level. A nested image can acquire an absolute URL after rehydration, fail server validation, and disappear from the client quota calculation. Traverse live and serialized ordinary groups while preserving signed catalog SVGs as individual placements.
4. **An excluded Theme Decor image can still be duplicated.** `static/js/design_canvas.js:2914` uses a quota check that explicitly permits a missing rule at line 2629. After switching offers, the customer can select a retained Theme Decor image and add another copy. Verify current inclusion for custom placements in both stages of cloning. The existing placement should remain available for removal.
5. **Abandoned edits permanently retain private uploads.** `app/views/canvas_uploads.py:55` binds a newly uploaded file to an existing design before Save. Closing the editor can leave its ID absent from the saved library while the relationship excludes it from cleanup. Defer the durable relationship until the customer saves the draft.
6. **Concurrent saves can pair a layout with another tab's upload library.** `app/views/designs.py:225` stores the layout before line 247 replaces the relationships, with independent commits. Interleaved saves or a failed relationship update can leave a saved image eligible for deletion. Commit the canvas and retained upload set together, serialize updates to the design, and coordinate attachment with orphan cleanup.
7. **Browser draft ownership is only partially enforced.** `static/js/design_canvas.js:1171` checks the account before restoring the image registry, but line 1177 loads the cached canvas and the preceding lines can change offers. Two signed-in customers using the same browser and new-design URL can restore the previous customer's layout. Reject a draft carrying a different explicit owner before restoring any of its content. Historical drafts without an owner need a separate compatibility decision.
8. **Booking retention omits hidden images referenced by the submitted layout.** `app/design_reference_snapshot.py:14` collects visible objects, and line 38 retains only their images. The snapshot still contains the full submitted canvas. A hidden but valid customer image can therefore be purged after the source design is deleted. Retain every verified upload referenced by the submitted layout and use visibility only for the breakdown and quantity.
9. **Package-change notices omit catalog-only submissions.** `app/templates/admin/booking/workspace/_references.html:6` guards the mismatch notice with a nonempty custom breakdown. An administrator reviewing a catalog-only layout after a package change receives no notice. Show the notice for every versioned reference snapshot with a changed package while preserving historical previews.

## Additional behavior affecting the fixes

- The client currently accepts a matching upload ID and token with mismatched category, source, or catalog metadata in `static/js/design_rules.js:5`. The server rejects it in `app/canvas_uploads.py:119`. Include identity parity in the grouped-design fix so a malformed restored draft cannot show a false quantity or package upgrade. Prospective upload objects used for upgrade checks need the same canonical fields.
- Both evaluators read normalized declared balloon colors from upload records. I found no separate discrepancy for ordinary well-formed declarations.
- Ordinary catalog categories still require eligible defaults, and the Styrofoam Name text preset remains distinct. The package conversion names match the four approved packages and Stand B.

## Scope and verification

I reviewed the working-tree package and actual source without running Django tests, changing database state, or editing the implementation. The supplied verification included baseline and focused Django tests, Node rule and upgrade tests, and a desktop browser check. The mobile rerun and full suite were in progress. I did not independently assess runtime mobile appearance, hosted storage behavior, or deployment data contents.

I found no independent multi-selection serialization defect. Save discards the active selection and the duplicate action accepts a single object. Persisted Fabric groups follow a different path and are covered by finding 3. The worker can expire unattached browser-only drafts after 24 hours. The specification permits cleanup of abandoned uploads but gives no exact retention duration, so I did not classify the interval itself as a defect.
